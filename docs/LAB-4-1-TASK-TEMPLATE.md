# Task Spec Template

Fill in each section before handing this to an agent. Blank on purpose —
this is the skeleton, not a filled example.

## Blast radius

*Which files, modules, or routes does this change touch or risk
affecting — including ones it should NOT need to touch? Name the
existing, already-tested behaviour that must still work unchanged when
this is done.*

-

## Definition of done

*What must be true for this task to be complete? Prefer concrete,
checkable statements (status codes, exact response shapes, specific test
names) over adjectives like "robust" or "clean".*

-

## Patterns to follow

*Which existing file(s) in this repo is the new code supposed to look
like? Point at the actual reference files, not a general style
description.*

-

## Out of scope

*What is adjacent, tempting, and NOT part of this task? Name specific
files or behaviours an agent might be tempted to touch or "fix" along
the way, and say explicitly: leave them alone.*
